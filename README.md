## 这一版（v1.5.0）最值得看的五件事

对标 v1.4.5，这一版的改动量是「换底座」级别：后端模块 **7 → 102**，单测 **0 → 122 个文件**，验收 **1 道自检 → 9 道门禁 + 浏览器通道专项冒烟**。

| 它是什么 | 为什么值得单独说 |
| --- | --- |
| **浏览器快车道** | 装一个扩展，它就能直接读当前页正文、开页面、点元素、输入——**不碰你的鼠标键盘**，也不用「截图猜坐标」。只认 17 条白名单命令，`eval` / `cookie` / `upload` 永远拒绝 |

| **治理四档** | 「专家团」和「Max」是两个正交开关。开了团队才有团队治理；重治理（封驳评审 + 多 agent 带上下文）严格绑定「专家团 + Max」 |

## 先说安全：它会动你的鼠标，所以先给了急停

把鼠标键盘交给 AI，你第一个问题一定是「它乱来怎么办」。ORB 把这件事当成第一功能来做：

| 机制 | 说明 |
| --- | --- |
| **急停** | `Ctrl + Alt + Backspace` 一键中断，或顶栏红色急停按钮。前台、后台、排队中的任务一起停，恢复前不再接受新任务 |
| **急停不硬杀** | 全局暂停只挡新工单，**正在跑的不硬杀**——硬杀会留半截状态。要它停在安全点上，不是停在半路 |
| **权限分级** | 只读 / 工作区可写 / 完全访问三档，随会话保存，切换即时生效。不开「完全访问」就不会有视觉循环 |
| **能力时钟** | 每一次「副作用」都签发 capability，执行前后校验是否仍属当代。换档期间老指令失效，不会「上一档的活插到这一档来」 |
| **观察边框** | 前台执行时目标窗口亮起一圈边框，你能实时看到「它正在操作谁」 |
| **人工确认** | 删除、支付、发送等不可逆操作，模型必须先发起确认；浏览器写操作也必须显式带 `confirm` |
| **令牌鉴权** | 桥接层每个接口都要启动时随机生成的 `X-Orb-Token`，浏览器里的任意网页无法遥控你的电脑 |
| **凭据不进日志** | 日志总线做枚举校验 + 白名单 + 脱敏转义，key 只在内存里过一遍 |
| **零遥测** | 项目不含任何联网遥测；「机器遥测」模块只做**只读一次性快照**，不外发 |
| **记忆只在本地** | 长期记忆是一个本地 JSON 文件，召回与压缩都在本机完成；除拼进你自己的任务上下文，不外传 |

## 四条轨道 + 一个模式

同一句自然语言，ORB 会自己判断该走哪条路；你也可以手动指定。

| 轨道 | 干什么 | 适合 |
| --- | --- | --- |
| **前台轨道** | 直接操作你的电脑：点击、输入、快捷键、滚动、长按、拖动、截图看屏幕 | 打开软件、填表单、整理文件这类「手上的活」 |
| **后台轨道** | 把重活派给 Agent（headless 一次性执行），**答案边跑边长出来**，跑完回填 | 读代码库、写长文档、跑批处理这类「动脑的活」 |
| **视觉轨道** | 「截图 → 视觉模型 → 动作 → 再截图」的闭环，模型自己决定下一步点哪里 | 没有 API、只能靠看的软件 |
| **浏览器轨道**（v1.5.0） | 通过扩展直接指挥标签页：读正文、开页、点、输入、滚。不占鼠标 | 查资料、抓网页、填网页表单 |
| **专家团模式**（v1.5.0） | 你只跟分配者对话，它把任务切给工作者，并行推进 | 一件活能拆成几块同时干的时候 |

前四条里「前台 / 视觉 / 后台」可以在输入框上方手动指定，「浏览器」由它在判断出是网页类任务时自动走
（不给你一个「我要用浏览器」的档位，是因为这件事它判断得比人快：网址、站名、抓正文，都是明确信号）。
「专家团」是顶栏的独立开关，和通道正交——开着它也可以让任务走后台。

视觉轨道的坐标用 **千分比（0–1000）** 而不是像素，避免高分辨率下模型数错位置；
支持主动 `zoom` / `reset` 调整视野；主力模型失败自动切备选。

## 浏览器快车道：不碰键鼠，也能「去那个网站看看」

以前让它「打开某个官网，把正文抓下来」，只有一条路：截图 → 视觉模型找坐标 → 点。慢、易错、还占着鼠标。

这一版加了一条真正的快车道：**面板 → 本机桥 → 原生宿主进程 → 浏览器扩展 → 标签页**。
在浏览器里加载 `orb/browser-extension/`，面板就能直接和标签页说话。

### 只认这 17 条命令

不是「什么都能干」，是硬编码白名单：

| 类别 | 命令 |
| --- | --- |
| 读（8 条） | `tab.list` `tab.url` `tab.title` `browser.info` · `dom.get_page_text` `dom.get_visible_dom` `dom.get_text` `dom.get_attributes` |
| 写（9 条） | `tab.open` `tab.goto` `tab.back` `tab.forward` `tab.reload` `tab.focus` · `dom.click` `dom.type` `dom.scroll` |

写操作**必须带 `params.confirm === true`**，不带直接拒。
`cua.*` / `cookie.*` 整个家族、`eval` / `upload` / `submit` / `script.execute` 及其子命名空间**永远拒绝**——
不给「任意 JS 执行」留后门，哪怕将来有人误加白名单也不放行。

### 取正文为什么单开一条命令

最早想用「把每个元素的 `textContent` 拼起来」凑正文，实测不可用：父元素包含子元素，正文重复 N 遍；
内联 `<script>` / `<style>` 也会一起进来，于是「提取网页文字」提取出一堆 `function(` 和 `{display:flex}`。

所以新增 `dom.get_page_text`：用 `TreeWalker` **只走可见文本节点**，跳过 `script/style/noscript/template`。
实测某高校官网首页：**1112 字 / 96 个文本块**，`function(` 与 `{display` 命中数都是 **0**。
拿到正文之后，`/api/export` 一条命令落成 txt（实测 2686 字节），不用你再复制粘贴。

### 读一下页面，不在你的标签栏留痕迹

早期版本「接管」标签页时会顺手 `chrome.tabs.group` 建一个 ORB 分组、改标题改颜色。
问题是：**只是让它读一下当前页的文字，标签栏却冒出一个分组**——这是侵入，不是功能。

这一版把分组逻辑整个删掉（不留开关，留着就迟早有人再打开），只登记所有权用于急停后清理；
老版本遗留的 ORB 分组仍会在急停 / 关通道时被拆掉。

## 治理：四档矩阵，两个开关各管一件事

以前只有一个「权限三档」，「要不要多花点力气把事办好」这件事没地方表达。这一版把它拆成两个正交开关：

| 档位 | 专家团 | Max | 启用的治理层 |
| --- | --- | --- | --- |
| 普通（默认） | 关 | 关 | 无 |
| 普通 + Max | 关 | 开 | 无（Max 只放大单 agent 并行强度） |
| 专家团（轻量） | 开 | 关 | 轻治理：代价路由 / 文件化信道 / 证据标注 / 亲测验收 / 协作红线 / 家规 |
| 专家团 + Max（满血） | 开 | 开 | 轻治理 + **重治理**：封驳评审（门下省）+ 多 agent 带上下文 |

硬约束写在代码里，不允许被「优化」掉：**没有团队就没有任何团队治理**；
Tier A（封驳评审）严格绑定「专家团 + Max」，Tier B（轻治理）绑定「专家团」、不看 Max。

「专家团」是**任务分配机制**（orchestrator-workers），不是审查开关——开它不会让每一条回复多一道复核，
而是让一件能拆的活真的并行拆开干。

v1.4.0 给工作流加了「遇到意外怎么办」四档策略，这一版把**运维侧**补齐了：

| 能力 | 说明 |
| --- | --- |
| **回放前预检** | 开跑之前先查：目标窗口在不在、锚定文字还找不找得到。别等点到一半才发现界面换了 |
| **断点续跑** | 跑一半失败，从检查点接着跑，不用从头再来（一个配方一个 json，跑成功即作废） |
| **配方版本** | 每次改动留版本，能看 diff、能回滚 |
| **运行账本** | runId / 步骤 / 耗时 / 结果 / 失败分类，全部来自既有账本——**不补零、不编数** |
| **回收站** | 删掉的配方进回收站，能恢复，过期才清 |
| **失败分类与有限重试** | 按错误类型判断「值不值得重试」；幂等键相同的不重复执行 |
| **结果判定** | 不靠模型说「我做完了」：先收界面证据、再定判据、最后独立判定 |

## 存储：一个根，按类型分，按天分层

以前录屏在 `recordings/`、截图在 `screenshots/`、导出在别处、日志又在另一处。现在收敛成一个用户可见的根：

```
ORB存储/
  recordings/  screenshots/  vidx/  exports/     ← 成品：<类型>/<日期>/<文件名>
  archive/<日期>/                                ← 归档：东西还在这儿，只是不碍眼
  logs/<日期>/                                   ← 运行日志按天分层
  governance/  history/  misc/
```

约定：存储根下只允许上面这些目录，**不允许出现根级 `<YYYY-MM-DD>` 日期目录**
（历史包袱曾经有过，后来统一收到 `archive/<日期>/` 下）。

第一次启动会问你要不要「搬过来」；离线迁移脚本同样只复制不删除、目标同名文件跳过、重复跑幂等。

便携版是**自解压单文件**：运行后把自己展开到 `%LOCALAPPDATA%\ORBConsole` 并启动，
不安装、不写注册表、不需要预装 Node 或 Python（运行时随包自带）。

包里那 220 MB 中约有 9 MB 是**离线语音包**——360 句预生成语音，装完就能出声，不用联网、不用配接口。

- 数据目录：`%APPDATA%\ORB 控制台`（成品在 `ORB存储/` 下）
- 卸载：运行同目录下的 `卸载 ORB 控制台.cmd`
- 首次运行如遇 SmartScreen 提示，选「更多信息 → 仍要运行」（发布物尚未签名，见下文）
- GitHub 会把发布资产的文件名强制转成 ASCII，中文名显示在每个资产右侧的说明文字里

### 从源码运行

```bat
:: 前置：Windows 10/11 x64、Node.js 22+
npm install --prefix orb
npm install --prefix orb/desktop

:: 起面板
双击「启动 ORB 控制台.cmd」
```

### 首次使用

1. **配置视觉模型** —— 设置（顶栏齿轮）→「视觉模型」，填接口地址、模型名、API Key。
   没有 key 时可选「自检」预设，用脚本化响应跑通除第三方接口外的全部环节。
2. **选择权限** —— 状态条右侧滑轨，日常用「工作区可写」。
3. **直接说** —— 例如 `打开记事本`、`截个图`、`把这段代码整理成文档发到桌面`。
4. **想让它碰浏览器** —— 加载 `orb/browser-extension/`，然后 `打开某某官网，把正文存成 txt`。

### 两条音源与四态

| 离线语音包 | 生成播报 | 包里有的句子 | 包里没有的句子 |
| --- | --- | --- | --- |
| 开 | 开 | 播离线包 | 回落生成播报 |
| 开 | **关** | 播离线包 | **静默不出声** |
| 关 | 开 | 走生成播报 | 走生成播报 |
| 关 | 关 | 不出声 | 不出声 |

第二行是真正解锁的能力：**只留离线包，一句都不联外网**。代价是模型现编的那些句子没声音，
但台词气泡照旧显示在对话里，所以你不会漏掉它说了什么。

### 长期记忆：会自己挑，也会自己瘦身

| 层 | 取用 |
| --- | --- |
| soul / user / rules | **常驻注入**（人格、偏好、规则） |
| project / fact / lesson / topic | **按当前任务检索** top4 |

分层不是为了「分类好看」。拿 18 条查询实测过：分层和一大坨平铺的命中率一模一样（都是 18/18），
但平铺方案里「规则 / 偏好 / 人格」命中 **0 条**——检索只挑和查询词相关的，
而「别用 tab 缩进」这种规则永远不含查询词。这才是分层的真实价值。

| 压缩机制 | 数值 |
| --- | --- |
| 触发闸 | 单层活跃字数 ≥ 6000，或全库 ≥ 14000（也可手动点「压缩」） |

| 熔断 | 冷却 10 分钟；连续失败 3 次自动停手，不再反复烧额度 |

## 常见问题

**会让 AI 在我不知情的情况下操作电脑吗？**
不会。不开「完全访问」权限就没有视觉循环，前台动作都有观察边框，`Ctrl + Alt + Backspace` 随时中断。
浏览器通道的写操作必须显式带 `confirm`，`eval` / `cookie` / `upload` 一律拒绝。

**必须装 CodeBuddy / WorkBuddy 吗？**
后台轨道需要你本机装有 CodeBuddy CLI。前台轨道、视觉轨道、浏览器轨道、录屏、截屏不依赖它。

**没有视觉模型的 API Key 能用吗？**
能。设置里选「自检」预设，可用脚本化响应跑通除第三方接口外的全部环节。

**浏览器通道会不会在我标签栏里建分组？**
不会。这一版把建分组的逻辑整个删掉了——读一下页面不该在你的界面上留痕迹。

**只让它读正文，为什么要装扩展？**
因为不装扩展就只能截屏猜坐标。装了之后是直接读 DOM，快、准、不占鼠标，而且有白名单兜底。

**插件会不会乱来？**
插件执行体是同进程 JS，需要构建期内置；危险能力必须显式审批；产出要过验收闸门。
换句话说它不是「随便下载个脚本就跑」，而是「拖进来的包必须能说清自己要什么」才装得上。

**不联网能有声音吗？**
能。离线语音包有 360 句，装完直接出声；联网的生成播报是可选项，不配也能用系统语音兜底。

**为什么有时候它说话了却没声音？**
看「设置 › 个性 › 声音」里的「② 生成播报」是不是关着。关掉它的意思是「一句都不联外网」，
那么离线包里没有的句子就**静默不播**——台词气泡还在对话里，只是没念出来。

**记忆压缩会删掉我的东西吗？**
不会。被合并的原文只是标成「已归档」：退出召回、不占预算，但内容和归档原因都留着，可回溯，90 天后才物理清理。
规则、偏好、人格这三层永远不参与压缩。

**我原来的录屏和截图呢？**
第一次启动会问要不要「搬过来」。迁移只复制不删除，源目录原样保留；重复跑也不会产生重复文件。

**为什么便携包有 220 MB？**
它自带 Electron 运行时、Node/Python 依赖，以及约 9 MB 的离线语音包，换来了「不装任何东西也能双击运行、开口就有声」。

**录屏能只录一部分屏幕吗？**
能。「设置 › 截屏与录屏 › 录制区域」里选半屏 / 中间 / 自定义框选。选的是相对屏幕的比例，换分辨率或改缩放后依然指得对地方。
