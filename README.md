## 先说安全：它会动你的鼠标，所以先给了急停

把鼠标键盘交给 AI，你第一个问题一定是「它乱来怎么办」。ORB 把这件事当成第一功能来做：

| 机制 | 说明 |
| --- | --- |
| **急停** | `Ctrl + Alt + Backspace` 一键中断，或顶栏红色急停按钮。随时可打断，不留后台动作 |
| **权限分级** | 只读 / 工作区可写 / 完全访问三档，随会话保存，切换即时生效。不开「完全访问」就不会有视觉循环 |
| **观察边框** | 前台执行时目标窗口亮起一圈边框，你能实时看到「它正在操作谁」 |
| **人工确认** | 删除、支付、发送等不可逆操作，模型必须先发起确认 |
| **令牌鉴权** | 桥接层每个接口都要启动时随机生成的 `X-Orb-Token`，浏览器里的任意网页无法遥控你的电脑 |
| **零遥测** | 项目不含任何遥测；密钥只在内存里过一遍，不落盘、不写日志 |
| **记忆只在本地** | 长期记忆是一个本地 JSON 文件，召回与压缩都在本机完成；除拼进你自己的任务上下文，不外传 |

## 三条执行轨道

同一句自然语言，ORB 会自己判断该走哪条路；你也可以手动指定。

| 轨道 | 干什么 | 适合 |
| --- | --- | --- |
| **前台轨道** | 直接操作你的电脑：点击、输入、快捷键、滚动、长按、拖动、截图看屏幕 | 打开软件、填表单、整理文件这类「手上的活」 |
| **后台轨道** | 把重活派给 Agent（headless 一次性执行），**答案边跑边长出来**，跑完回填 | 读代码库、写长文档、跑批处理这类「动脑的活」 |
| **视觉轨道** | 「截图 → 视觉模型 → 动作 → 再截图」的闭环，模型自己决定下一步点哪里 | 没有 API、只能靠看的软件 |

视觉轨道的坐标用 **千分比（0–1000）** 而不是像素，避免高分辨率下模型数错位置；
支持主动 `zoom` / `reset` 调整视野；主力模型失败自动切备选。

## 下载

| 方式 | 体积 | 说明 |
| --- | --- | --- |
| **便携单文件 `.exe`** | 约 220 MB | [Releases](https://github.com/zhoukr123/ORB-Console-made-for-workbuddy/releases) 下载 `ORB-Console-<版本>-portable.exe`，双击即用 |

| **从源码运行** | — | 需要 Node.js 22+，见下 |

便携版是**自解压单文件**：运行后把自己展开到 `%LOCALAPPDATA%\ORBConsole` 并启动，
不安装、不写注册表、不需要预装 Node 或 Python（运行时随包自带）。

包里那 220 MB 中约有 9 MB 是**离线语音包**——360 句预生成语音，装完就能出声，不用联网、不用配接口。

- 数据目录：`%APPDATA%\ORB 控制台`
- 卸载：运行同目录下的 `uninstall-ORB-Console.cmd`
- 首次运行如遇 SmartScreen 提示，选「更多信息 → 仍要运行」（发布物尚未签名，见下文）
- GitHub 会把发布资产的文件名强制转成 ASCII，中文名显示在每个资产右侧的说明文字里

### 从源码运行

```bat
:: 前置：Windows 10/11 x64、Node.js 22+
npm install --prefix orb
npm install --prefix orb/desktop

:: 起面板
双击「启动 ORB 控制台.cmd」
```

### 首次使用

1. **配置视觉模型** —— 设置（顶栏齿轮）→「视觉模型」，填接口地址、模型名、API Key。
   没有 key 时可选「自检」预设，用脚本化响应跑通除第三方接口外的全部环节。
2. **选择权限** —— 状态条右侧滑轨，日常用「工作区可写」。
3. **直接说** —— 例如 `打开记事本`、`截个图`、`把这段代码整理成文档发到桌面`。

### 录屏：只录一块（v1.4.5）

有时候整屏录下来，一大半是无关的桌面。现在「设置 › 截屏与录屏 › 录制区域」可以只录一块：

| 预设 | 覆盖范围 |
| --- | --- |
| 全屏 | 整块主屏（默认，不裁剪） |
| 左半屏 / 右半屏 | 半个屏宽、整屏高 |
| 上半屏 / 下半屏 | 整屏宽、半个屏高 |
| 中间 | 屏幕中间 70% × 70% |
| 自定义 | 弹一层全屏覆盖层，自己拖一个框 |

<p align="center">
  <img src="docs/shots/set-t1-rec.png" width="720" alt="设置 › 截屏与录屏：隐藏控制台开关在顶部，下面有录制区域预设">
  <br>
  <sub>↑ 「录屏 / 截屏时隐藏控制台」就在这一页顶部；下面是录制区域的预设与当前范围提示</sub>
</p>

两个细节决定了它用起来「准不准」：

- **存的是相对主屏的比例，不是像素**。换显示器、改缩放、拔掉副屏之后，原来的「左半屏」还是左半屏。
- **比例到像素的换算只在主进程做**（`主屏尺寸 × scaleFactor`）。面板拿到的是 CSS 像素，而采集要的是物理像素，差一个缩放倍数——算错的表现就是「以为录左边、成片是中间」。渲染层只传 0..1 的比例，一律不碰 DPI。

原生直出这条路径把范围交给 `orb-cap.exe --rect`（奇数边长向下取偶，编码器要求偶数）；
走 MediaRecorder 那条路径没法裁剪，所以改成 canvas 逐帧 `drawImage` 再 `captureStream(30)`——
用 `setInterval` 而不是 `requestAnimationFrame`，因为录制时面板是收起来的，rAF 会被系统节流到几乎停摆。

自定义框选那层覆盖层压在桌面上，底色恒定深（浅色面板遇上白窗口会让选框看不见），
但**强调色跟着面板主题走**（`--ac-rgb` / `--ac-on` / `--accent-grad` 三件套），
所以深空下是蓝、极光下是渐变紫，不会出现「面板一套色、浮层另一套色」的外来感。

### 摄像头小框：位置跟着录制区域走（v1.4.5）

录教程、录演示时想把自己搁在角上，以前只能整屏录才摆得准。现在小框的坐标系换成了**录制区域**：

| 项 | 可选 |
| --- | --- |
| 形状 | 圆形（等比缩放）/ 圆角矩形 / 方框（后两种可拖边调宽高） |
| 比例 | 16:9 / 4:3 / 1:1 / 自由，或填自定义长宽比（如 `1.78`） |
| 摆位 | 「预览摆位」在整屏上按真实比例拖动、拖边缩放，切形状与比例即时生效 |

关键在归一化：`bx / by` 是小框中心点、`bw / bh` 是宽高，四个数**都以录制区域为分母和原点**，
不是整屏。所以选「右半屏」之后小框不会落在画面外，可摆放边界与吸附目标也跟着录制区域一起收窄。
摆位层同样是深底 + 面板强调色，切主题不会闪成另一套色。

### 语音：两条并行音源（v1.4.5）

这一版把「声音」拆成了两条互不依赖的线，总开关之下各有各的开关：

|  | 是什么 | 联网 | 耗额度 |
| --- | --- | --- | --- |
| **① 离线语音包** | 360 句台词预生成成 opus 随包带（约 9 MB） | 不需要 | 不耗 |
| **② 生成播报** | 在线 TTS 接口，没配就用系统语音兜底 | 要（除非兜底） | 看你用哪个 |

四态怎么走：

| 离线语音包 | 生成播报 | 包里有的句子 | 包里没有的句子 |
| --- | --- | --- | --- |
| 开 | 开 | 播离线包 | 回落生成播报 |
| 开 | **关** | 播离线包 | **静默不出声** |
| 关 | 开 | 走生成播报 | 走生成播报 |
| 关 | 关 | 不出声 | 不出声 |

第二行是这次的关键：以前「关掉在线接口」只能连带把声音全关掉，现在可以**只留离线包**——
一句都不联外网，代价是模型现编的那些句子（带任务名、带具体措辞的）没声音。
但台词气泡照旧显示，所以你不会漏掉它在说什么。

  <sub>↑ 「① 离线语音包」「② 生成播报」并列；下面那行实时告诉你此刻哪条音源在出声、哪些句子会没有声音</sub>

### 在线语音合成（AI 念白）

「设置 › 个性 › AI 在线语音合成」里可以填任何 **OpenAI 兼容** 的语音端点：

| 字段 | 说明 |
| --- | --- |
| 合成引擎 | 「在线接口（OpenAI 兼容）」或「浏览器 / 系统语音」 |
| 接口地址 | 例如 `https://api.openai.com/v1/audio/speech`，自建网关也行 |
| API Key | 只在填新值时覆盖，读回只显示后四位 |
| 模型名 / 音频格式 / 默认音色 | 默认 `tts-1` / `mp3` / `alloy`，按你的服务商改 |
| 按人格指定音色与语气 | 五个人格各给一个音色与一句语气指令，留空就用上面的默认值 |

### 长期记忆：会自己挑，也会自己瘦身（v1.4.5）

记忆分七层，取用方式不一样：

| 层 | 取用 |
| --- | --- |
| soul / user / rules | **常驻注入**（人格、偏好、规则） |
| project / fact / lesson / topic | **按当前任务检索** top4 |

分成七层不是为了「分类好看」，是为了让**不含查询词但必须在场**的东西不被挤掉。
拿 18 条查询实测过：分层和一大坨平铺的命中率一模一样（都是 18/18），
但平铺方案里「规则 / 偏好 / 人格」命中 **0 条**——因为检索只会挑和查询词相关的，
而「别用 tab 缩进」这种规则永远不含查询词。这才是分层的真实价值。

常驻层还有 1200 字预算上限：按重要度、再按更新时间逐条填，装不下的直接丢尾，
末尾补一句「另有 N 条长期记忆因篇幅未注入」，不搞无声截断。

**会瘦身**是这一版新加的：

| 机制 | 数值 |
| --- | --- |
| 触发闸 | 单层活跃字数 ≥ 6000，或全库 ≥ 14000（也可以手动点「压缩」） |
| 只压哪几层 | `fact` / `lesson` / `topic` / `project`——规则、偏好、人格**永不参与**，合并有丢约束的风险 |
| 挑谁压 | 重要度最低的先压；同重要度里最旧的先压；同条件下内容长的优先 |
| 压不动就放弃 | 压完缩不到原字数 55% 就整单作废，原文一条不动 |
| 原文怎么办 | 标「已归档」：退出召回、退出预算，但留着可回溯，90 天后才物理清理 |
| 熔断 | 冷却 10 分钟；连续失败 3 次自动停手，不再反复烧额度 |

<p align="center">
  <img src="docs/shots/set-t1-memory.png" width="720" alt="设置 › 存储 › 记忆库：条数、字数、已归档数量与压缩键">
  <br>
  <sub>↑ 「记忆库」标题旁直接写清总数 / 字数 / 已归档条数，右边是「压缩」键</sub>
</p>

顺手还补了两个基础件：召回命中时会真的累加 `access_count` 与 `last_accessed_at`
（此前这两列写入一次 `null` 之后就再没动过，等于无法判断哪条真被用过），
以及自动记忆从「每完成一个任务就多跑一次模型」改成**攒到你停手 90 秒后批量提炼，一次最多 3 条**。

### 后台：推送代替轮询，还看得见首字延迟（v1.4.5）

面板和本机桥之间原来是定时问「好了没」。现在换成 SSE 推送：`/api/events` 推全局状态，
`/api/job/:id/stream` 推单个任务的流式片段，空闲时一次请求都不发。
面板不可见（`document.hidden`）时自动退回轮询——后台标签页里 SSE 会被掐，硬撑不如老实退。

顺带补了**首字延迟**（TTFT）埋点：总耗时只能告诉你「慢了」，说不清慢在哪一段。

| 位置 | 显示什么 |
| --- | --- |
| 状态行 | 本次任务的首字延迟，例如「首字 1.2s」 |
| 审计面板顶部 | 近 30 次任务的 p50 / p95，例如「首字延迟 p50 1.1s / p95 2.6s」 |

### 工作流：录完之后，还得扛得住改版（v1.4.0）

录制回放最容易翻车的地方不是录，是**放**：过两天按钮挪了位置、多了个弹窗，回放就一路点空。
现在每条工作流多了「目标」和「遇到意外怎么办」两个字段，四档策略自己挑：

| 策略 | 什么时候选 |
| --- | --- |
| 照录制坐标继续 | 不调模型，最快；点错了也没事的流程 |
| 停下来并报错 | 宁可不做也不乱点；会改数据的流程 |
| 先问一次视觉模型 | 卡住那一步问一次该怎么走 |
| 交给智能体顶几步 | 让视觉模型推回正轨，再交还回放 |

后两档只在**配了锚定文字、且那句话确实找不到**的步骤上触发，其余步骤永远纯回放，所以不会因为开了它就每条都变慢。

配套的还有：循环节点可配「轮次标记」（靠审计表数它执行了几次来推定完成几轮）；录完发现几段相同操作会建议折成循环但不擅自改；定时 / 文件 / 热键三类触发器搬进每条工作流的编辑面板底部。

### 个性系统：五个人格，和它们的台词（v1.4.0 / v1.4.1）

个性是一个**陪伴层**，和后台 AI 的回答是两条独立的线——人格不会去改 AI 回答的内容，只是旁边有个家伙在嘟囔。
在「设置 › 个性」里挑一个：温柔守护者 / 元气开心果 / 上进小战友 / 智慧小向导 / 正能量傲娇，
各自有台词库、口吻、颜文字和音色；悬浮球那七张动图也会跟着演。

念出来的台词现在会**显示在对话里**（小一号、淡色、左边一道细线），关了声音也照样有——
以前它们只走语音合成，一个字都不显示，等于个性隐身。默认还开了「精简念白」：
一个任务只在完成、失败、被夸这类有结果的节点念一句，「收到」「执行中」省掉，想听完整版可随时切回。

### AI 台词：现编的，但不是瞎说（v1.4.1）

台词不再全是写死的。打开「设置 › 个性 › AI 台词」（默认关）之后，每派一个任务会**多一次模型调用**，
这一次把整轮要用的话一次性生成好：过程三句、成功一句、失败一句。成本等同「结尾现编一次」，
但整个过程都有这个人格自己的说法。

分工划得很死：**什么时候说、说到第几句、说的是哪类动作，由程序按真实工具调用决定；这句话怎么措辞，由模型按人格决定。**
工具名会被映射成泛化动作（读文件 / 搜代码＝翻箱子，改文件＝动笔，跑命令＝拧螺丝，认不出的就不说），
所以它宁可少说一句，也不会编一个不存在的文件名。最多三句、同工具不重复、两句至少隔六秒。

任何失败（没配接口、接口挂了、超时、输出解不出 JSON）都静默退回预定台词，你看到的就是旧行为。
关掉开关则一次额外调用都不发生。

想让它说得更快、不占 CLI 额度，可以在「设置 › 通道 › 后台 Agent › 自定义模型」填自己的 OpenAI 兼容接口。
把「接管后台任务」开着，这个接口还能直接干活：控制台会把它注册进 CLI 的模型清单，派任务时交给 CLI 去调，
读文件、跑命令、调工具全是 CLI 在做。代价是你的接口得支持 function calling，模型名也要和接口文档写的一模一样。
它花掉的 token 会和台词那笔一起记在状态条与积分弹窗里，不会变成看不见的支出。

  │                 ▲
  │                 └─ 视觉轨道：截图 → 视觉模型 → 千分比坐标 → 动作 → 再截图

## 常见问题

**会让 AI 在我不知情的情况下操作电脑吗？**
不会。不开「完全访问」权限就没有视觉循环，前台动作都有观察边框，`Ctrl + Alt + Backspace` 随时中断。

**必须装 CodeBuddy / WorkBuddy 吗？**
后台轨道需要你本机装有 CodeBuddy CLI。前台轨道、视觉轨道、录屏、截屏不依赖它。

**没有视觉模型的 API Key 能用吗？**
能。设置里选「自检」预设，可用脚本化响应跑通除第三方接口外的全部环节。

**不联网能有声音吗？**
能。离线语音包有 360 句，装完直接出声；联网的生成播报是可选项，不配也能用系统语音兜底。

**为什么有时候它说话了却没声音？**
看「设置 › 个性 › 声音」里的「② 生成播报」是不是关着。关掉它的意思是「一句都不联外网」，
那么离线包里没有的句子（模型现编的那些）就**静默不播**——台词气泡还在对话里，只是没念出来。想听就把这一项打开。

**记忆压缩会删掉我的东西吗？**
不会。被合并的原文只是标成「已归档」：退出召回、不占预算，但内容和归档原因都留着，可回溯，90 天后才物理清理。
规则、偏好、人格这三层永远不参与压缩。

**为什么便携包有 220 MB？**
它自带 Electron 运行时、Node/Python 依赖，以及约 9 MB 的离线语音包，换来了「不装任何东西也能双击运行、开口就有声」。介意的话可以用源码方式运行。

**录屏能只录一部分屏幕吗？**
能。「设置 › 截屏与录屏 › 录制区域」里选半屏 / 中间 / 自定义框选。选的是相对屏幕的比例，换分辨率或改缩放后依然指得对地方。
