# v1.3.6 更新说明

这一版主要做一件事：**把散在各处的东西放回它们该在的地方。** Ctrl+K 不再是万能抽屉，设置面板里也不再是一长条没有段落的卡片。顺手修掉了「开始录制之后找不到停止键」这个真问题。

## Ctrl+K 现在只管找功能

以前按 Ctrl+K，一个搜索框里同时塞着四类东西：控制台的功能、录好的工作流、会话历史、还有触发器。搜一个「录」字，工具、工作流、会话一起跳出来，命中越多反而越难一眼挑到想要的。

现在 Ctrl+K 只留「功能」：搜到什么就执行什么。输入框的提示也从「搜索命令」改成了「搜索功能」。

工作流和会话各自有了正经入口：

- **工作流**（回放、改步骤、生成示例、用 AI 写一条）搬到 **设置 › 截屏与录屏 › 工作流**。
- **会话历史**回到顶栏那枚时钟图标，一直是它的本分。

留了个口子：急停、触发器、审计日志这三个仍在 Ctrl+K 里。它们没有别的入口，摘掉就等于功能消失——等它们有了各自的家再挪走。

## 设置里那页改名了，还分了段

「录屏」这页原来把录屏、截屏、工作流的卡片混成一长条，往下翻没有参照物，找什么全靠扫。现在它叫 **截屏与录屏**，里面切成三大块，每块一个框、一个大标题：

- **录屏**——音频来源、悬浮条、自动收起、描边这些录制本体的设置。
- **截屏**——Snipaste 的检测与重新检测、去官网。这块是从「存储」页搬过来的，跟截屏放在一页才说得通。
- **工作流**——已录好的列表，点名字直接回放，点「编辑」改步骤；下面两个按钮可以生成编排示例、或用 AI 写一条。

三块的标题右边都有一条交关线。平时只画左半截，鼠标移到哪一块，那条线就向右延展到底、并且染上当前主题的强调色——不用去看哪块高亮，视线自己就知道在对哪一块。「存储」页里的**截屏文件存储地址**原地没动，它属于存储，不属于截屏。

## 录制时终于有停止键了

这是个真 bug，不是样式问题：之前点「录操作」开始录制后，顶栏那枚键还是一枚在动的红色三角，看上去跟没录制时一个样——你根本不知道它已经变成停止键了，于是「只有按键动效、没有停止键」。

现在录制中它会**变成一枚红底白方块**，并且以 1.3 秒的节奏明暗呼吸，一眼就知道「在录、点它结束」。开始录制的提示也写清楚了：做完点顶栏那枚红色方块即可完成并保存。它的说明文字也从「停止」改成了「完成」——这一步是保存，不是中断。

## 工作流步骤的图标重画了

步骤编辑器里，循环、判断、变量这三类步骤本来各有各的图标，但取图标的那行代码写成了「只有普通动作才取工具图标，其余一律用占位图」——结果三类步骤全都显示同一个圆圈问号，看着就像图标全错了。

现在四类图标各自按通用图标规范重画，都是 24×24 网格、2px 描边、跟着文字色走：

- **动作**——播放三角
- **循环**——一上一下两个追逐的箭头
- **判断**——分支（两个端点圆 + 一条连线）
- **变量**——一对花括号 `{ }`

工作流弹窗（列表与步骤编辑器）的边框也跟着主题走了，用的是当前主题的强调色，切主题时和底色一起做 0.22 秒的交叉淡入，不会「啪」一下换色。

## 顺手清掉的死代码

- 工具行重构时删掉的两枚常驻键（录制、急停），它们对应的 JS 分支一直留着在空转——`#toolRec` 那条正是「找不到停止键」的根源所在，一并删掉。
- 工作流列表弹窗：工作流迁到设置页后它已经没人能打开了，删。
- 发送栏那个坐标显示元素早就按要求摘掉了，只写它的 `coordText()` 还留着，删。

## 已知问题

没有代码签名证书，第一次双击时 Windows SmartScreen 会拦一下，点「更多信息 → 仍要运行」即可。

## 本轮做的检查

这一版是照着「别再出那种低级 bug」的思路过的，所以在打包前做了几轮静态与运行时核验：

- **悬空元素引用**：全量扫了四个 HTML 里所有 `getElementById` / `#id` 引用，确认每个都有对应的 DOM 元素（之前那类「少个元素导致后面整段脚本静默失效」的问题就是这么来的）。四个文件现在都是零悬空。
- **语法与结构**：内联脚本过了一遍语法检查；`<body>` 里的标签做了配对校验，无交叉不匹配。
- **令牌与类名**：新增的 CSS 只用已定义的令牌（这一版刻意避开了不存在的圆角档位），JS 里用到的类名也都有对应样式规则。
- **IPC 白名单**：面板里 61 处 `window.orb.*` 调用逐个比对 preload 白名单，无越权。
- **定时器**：所有 `setInterval` 都有停止路径，没有裸循环。
- **无头浏览器实跑**：拿 Chrome 无头加载真实页面，对这次的改动做了 50 多条断言——三个板块的结构与标题、截屏块的迁移、存储地址没被动、四个工作流元件的位置、完成键的三角↔方块切换、四类步骤图标的语义与渲染、Ctrl+K 的分组与条目、以及**四套主题下**板块描边 / 交关线底色 / 弹窗主题色描边 / 完成键反色是否都跟主题走。全部通过，加载期无未捕获错误。

顺带记一条排查经验，免得以后再踩：无头浏览器里读样式会撞上两个假故障——元素有 `transition` 时，刚加上类立刻读会读到过渡起点的值（连 `!important` 都压不动）；元素在 `display:none` 子树里时，`transform` 一律返回 `none`。两条都让人误以为样式规则没生效，实际规则没问题。

## 下载

发布页两个文件，挑一个：

- `ORB-Console-1.3.6-portable.exe`——单文件，双击即用，首次启动解压到本机。
- `ORB-Console-1.3.6.zip`——完整目录，不想多占一份解压空间选这个。

都不用装 Python、Node 或别的运行库。

## 第一次打开

会先过一遍首跑向导，前台、语音、视觉、后台四条通道逐条体检，能用的会打上勾。想用截屏先装 Snipaste；想用后台长任务，装 CodeBuddy CLI 并登录。拿不准的时候记住 `Ctrl + Alt + Backspace` 是急停，随时能打断。
