### 1. 插件页按钮竖排（截图发现）

`.plug-tools` 是 `display:flex`，但按钮默认 `flex-shrink:1`：设置卡正文区在 560px 窗口下只有 126px 宽，
三颗「双字」按钮被压到 20 多像素，文字逐字换行 —— 看起来就是竖着堆了三个按钮。

改法：按钮 `flex:0 0 auto` + `white-space:nowrap`，内边距 8px→6px、间距 6px→5px（36×3+10=118 ≤ 126，排得进一行），
容器加 `flex-wrap:wrap` 兜底 —— 真放不下时整颗换行，而不是拆字。

`set-t1-plugins` 场景原来塞的字段（`what/version/kind`）在 `plugin.list` 里根本不存在，

改成照抄真实形状（`brief/level/inputs/outputs/builtin`），并核对了 `builtin:true` 的按钮差异（内置无「卸载」）。

## 用户反馈的一个真问题：标签页分组「又出现了」

不是回归，是**浏览器跑的还是旧脚本**。证据链：

- 已加载扩展路径（Chrome 与夸克一致）：`D:\workbuddy_ORB控制台\orb\browser-extension`，路径没错；
- 该目录下 `background.js` 已无 `chrome.tabs.group`，只剩 `ungroupOwnedTabs`；
- 磁盘上另一份带建组代码的副本是 `dist/ORB控制台-1.4.9-202611061112/.../background.js`（11-05 构建，且没有 `dom.get_page_text`）；
- 分组逻辑是 11-09 凌晨才删的，而用户上一次点「重新加载」在这之前 → 内存里仍是旧脚本。

处置：给扩展加 `BUILD` 构建戳（`browser.info` 会报回来），并在 README / 使用说明 / 更新说明三处写清
「改过扩展必须手动重新加载，否则修好的行为看起来又回来了」。
