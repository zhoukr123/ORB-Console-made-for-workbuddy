# ORB 控制台 · 打包与发布说明

> 面向"把这个控制台交给别人 / 发到 GitHub"的场景。
> 本文记录**怎么打包、包里有什么、为什么这么放**，以及发布时的注意事项。
> 本次交付的成品在仓库的 `dist/发布/` 目录。

---

## 1. 本次实际采用的路线（已跑通，产出单文件 .exe）

```
node orb/pack.cjs   （零网络，一条命令到底）
   ├─> dist/ORB控制台-1.0.0-<时间戳>/      便携目录
   ├─> dist/ORB控制台-1.0.0-<时间戳>.zip   便携目录 zip
   └─> dist/ORB控制台-1.0.0-<时间戳>-便携版.exe   ← 单文件，可直接发 GitHub
```

**为什么自己写自解压桩**：electron-builder 的 portable 目标需要从 GitHub 拉 SFX 模块，
本机代理对 GitHub 返回 502，构建必然失败。那就换 Windows 内置的 IExpress —— 结果
IExpress 对本次 payload **稳定失败**（CAB 完好、能正常展开，但卡在最后的合并步），
成败取决于 payload 的具体字节。最后改为**自研桩 `native/src/orb-sfx.c`**，
格式完全可控、可复现、零外部依赖。完整排查记录见 §7。

`pack.cjs` 现在一步产出全部三种形态：便携目录、zip、单文件 exe。

## 2. 怎么重新打包

### 唯一一步：`node orb/pack.cjs`（零网络）

```bash
node orb\pack.cjs            # ROOT 按脚本自身位置反推，克隆仓库后可直接跑
ORB_ROOT=<别的目录> node orb\pack.cjs   # 特殊场景才需要覆盖
```

产物（全部在 `dist/`）：

| 产物 | 说明 |
|---|---|
| `ORB控制台-1.0.0-<时间戳>\` | 便携目录，解压 zip 后的内容 |
| `ORB控制台-1.0.0-<时间戳>.zip` | 便携目录的 zip |
| `ORB控制台-1.0.0-<时间戳>-便携版.exe` | **单文件便携版**（桩 + zip + 32B trailer） |

- 直接复制本地 Electron 运行时，**完全不联网**
- 输出目录**带时间戳、不覆盖旧构建**（早先是一把 `rmSync` 清空，
  但批量删除会触发安全保护被拦截，故改为版本化目录，旧的由用户自行清理）
- 封装单文件后会自动做结构校验：把 trailer 反推的 payload 与原 zip 做
  **逐字节比对 + CRC32 校验**，对不上直接构建失败

### 前置：编译自解压桩（只需一次，改了 `orb-sfx.c` 才需要重跑）

```powershell
powershell -ExecutionPolicy Bypass -File orb\native\build-sfx.ps1
```

产出 `orb/native/dist/orb-sfx.exe`（约 138 KB）。脚本末尾会做一次自检：
拿没有 payload 的裸桩跑 `--probe`，**必须返回非零退出码**（证明它能识别"这不是包"）。
`build-sfx.ps1` 找不到桩时，`pack.cjs` 会明确跳过单文件步骤并提示，
目录版与 zip 不受影响。

### 自研桩的工作方式

文件布局三段，尾部自带寻址信息，因此**桩可以独立重编译、不需要同步任何常量、
也不需要给桩补零对齐**：

```
[ 桩本体 ][ payload zip ][ 32 字节 trailer ]

trailer：
  +0   8 字节  魔数 "ORBSFX1"
  +8   8 字节  payload 长度（小端 uint64）
  +16  4 字节  payload 的 CRC32（0 表示不校验）
  +20  12 字节 保留，全零
```

运行流程：

1. 读自身尾部 trailer，反推 payload 偏移 → 写到 `%TEMP%\orb-sfx-<pid>.zip`
2. 解到 `<目标>\_raw`（优先系统自带 `tar.exe`；没有则退 PowerShell `Expand-Archive`）
3. 在 `_raw` 里找唯一子目录，再找其中的 `*.cmd`，`cmd.exe /c` 拉起来
4. 删掉临时 zip

细节：

- 默认解到 `%LOCALAPPDATA%\ORBConsole`；也可 `orb-sfx.exe D:\some\dir` 指定目标
- **已解压过就跳过**：若 `_raw\<子目录>\resources\app\main.js` 已存在，直接启动，
  不再重复解 490MB
- 解压失败时**保留临时 zip** 并把路径显示给用户，让人能手动解开，而不是当场删掉
- `--probe` 静默模式：只回退出码、不弹窗（构建自检用；桌面锁屏时 `MessageBoxW`
  可能既不显示也不返回，自检会假死）
- 退出码：`0` 成功 / `1` 自身不是合法包 / `2` 解压失败 / `3` 找不到启动器

**桩的编译要点**（都在 `build-sfx.ps1` 里注释了）：

- `/SUBSYSTEM:WINDOWS`（双击不闪控制台）**必须**配 `/ENTRY:wmainCRTStartup`，
  否则 GUI 版 CRT 找 `WinMain`，链接报 `LNK2019`
- `/D_CRT_SECURE_NO_WARNINGS`：所有 `_snwprintf`/`wcsncpy` 调用点都带显式长度
  并手工补 `\0`，C4996 是误报

### 合成包联调（改桩之后跑一遍）

```bash
node orb\native\test-sfx.cjs
```

不依赖 490MB 真实构建，用几十 KB 的合成包验证全链路：
桩自寻址 → 解压 → 找到 `.cmd` → 拉起（启动器写标记文件）→ 清理临时 zip →
二次运行跳过重复解压。六项断言全过才算通过。

### 备选：electron-builder（网络可用时）

`orb/desktop/package.json` 里已配好（`asar:false` + 完整 `extraResources`）：

```bash
cd orb/desktop
npx electron-builder --win portable
```

本机当前**跑不通**：代理对 GitHub 返回 502，portable 目标的 SFX 模块拉不下来。
网络恢复后这是更标准的路线（产物同样是单文件 exe）。

## 3. 包内布局与"为什么在这儿"

```
ORB控制台-1.0.0-便携版.exe
（解包后落到 %LOCALAPPDATA%\ORBConsole\_raw\<时间戳目录>\，等价于下面这个结构）

├─ ORB 控制台.exe            ← electron.exe 改名而来（必须改名，见 §4）
├─ resources/
│   ├─ app/                   ← 应用本体
│   │   ├─ main.js            ← Electron 主进程
│   │   ├─ preload.js
│   │   ├─ panel.html / ball.html / border.html / subtitle.html / toolbar.html
│   │   ├─ voice.js
│   │   └─ selection-watch.ps1   ← 划词监听的 PowerShell 兜底（原生版见下）
│   ├─ bridge.mjs             ← 本地桥接服务（MCP + HTTP :19387）
│   ├─ mousehook.mjs          ← 鼠标钩子，bridge.mjs 动态 import
│   ├─ bridge.conf            ← 桥自身配置（daemon 开关）
│   ├─ node_modules/          ← 桥的依赖 @modelcontextprotocol/sdk
│   ├─ native/dist/
│   │   ├─ orb-foreground.exe ← 前台窗口探针（常驻）
│   │   ├─ orb-selection.exe  ← 划词监听探针（常驻，原生化版）
│   │   └─ orb-input.exe      ← Win32 SendInput 键鼠模拟
│   ├─ runtime/python/        ← 前台通道自带 embeddable CPython + 精简 site-packages
│   │   ├─ python.exe           （含 windows-mcp / pywin32 / pillow，约 124 MB）
│   │   └─ LICENSE.txt         ← PSF 许可，再分发必须附带（pack.cjs 硬校验）
│   └─ asr/                   ← 本地语音识别**源码**（约 100 KB，不含 venv / 权重）
│       ├─ asr_server.py / subtitle_rt.py / download_model.py / prepare.ps1
│       ├─ requirements.txt   ← 首跑一键安装时装什么
│       └─ asr.conf           ← 默认 small + device:auto
│   └─ extras/
│       ├─ 使用说明.md         ← 首次启动释放到 %APPDATA%\ORB 控制台
│       └─ workflows/*.json   ← 示例工作流，同样种子到 APPDATA
└─ 使用说明.md / approvals.json / 启动 ORB 控制台.cmd
```

> `runtime/python` 与 `asr/` 是"下载后即可使用全套功能"的关键：
> 前者让前台自动化不再寄生在 WorkBuddy 的 venv 上（干净机没有 WorkBuddy 也能跑），
> 后者让语音识别变成"点一次按钮按需安装"，而不是整包多背 2 GB。
> **`asr/` 里严禁出现 >1 MB 的文件** —— `pack.cjs` 对此有硬校验，超了直接构建失败。

> 中间那层 `_raw` 不是多余：桩要能判断"这份包是不是已经解过了"，
> 于是先解到 `_raw` 再看里面有没有完整的子目录。二次启动据此跳过解压
> （实测 6.4s → 1s）。

**路径契约（改代码时最容易踩的坑）**：

| 谁 | 怎么定位 | 打包后落在 |
|---|---|---|
| `main.js` 找桥 | `path.join(__dirname,"..","bridge.mjs")` | `resources/bridge.mjs` |
| `main.js` 找令牌 | `path.join(__dirname,"..",".bridge.json")` | `resources/.bridge.json` |
| `main.js` 找原生探针 | `path.join(__dirname,"..","native","dist","orb-foreground.exe")` | `resources/native/dist/orb-foreground.exe` |
| `main.js` 找划词监听器 | `path.join(__dirname,"..","native","dist","orb-selection.exe")` | `resources/native/dist/orb-selection.exe` |
| `bridge.mjs` 找 orb-input | `path.join(HERE,"native","dist","orb-input.exe")` | `resources/native/dist/orb-input.exe` |
| `bridge.mjs` 找 mousehook | `await import("./mousehook.mjs")` | `resources/mousehook.mjs` |
| `bridge.mjs` 找依赖 | Node 按自身位置向上找 `node_modules` | `resources/node_modules` |
| `bridge.mjs` 找前台通道 Python | `runtime.mjs` 的 `resolvePython()`：`ORB_PY_EXE` → 随包 `runtime/python` → `ORB_BASE_PY` → PATH | `resources/runtime/python/python.exe` |
| `bridge.mjs` 找 ASR | `ASR_DIR`（`ORB_ASR_DIR` 可覆盖）→ `<包>/resources/asr` | `resources/asr/asr_server.py` |

→ **任何一项漏打包，对应功能在发布版里就是坏的**，而开发态完全正常、测不出来。
`pack.cjs` 的校验清单已把这些列为硬校验（缺一个直接构建失败）。

## 4. 打包态 vs 开发态的行为差异

| 项 | 开发态 | 打包态 |
|---|---|---|
| 数据目录 `DATA_ROOT` | 项目根（克隆的仓库目录） | `%APPDATA%\ORB 控制台` |
| 会话历史 / 工作流 / 审批单 / 触发器 | 写在项目根 | 写在 APPDATA |
| Electron `userData` | 默认 | 被显式设到 `DATA_ROOT/.orbdata` |
| 令牌文件 | 项目根 `.bridge.json` | `resources/.bridge.json`（resources 是真实目录，可写） |
| Node 运行时 | `node.exe` | 优先 WorkBuddy 的 node；没有就用**应用自带的 electron.exe**（`ELECTRON_RUN_AS_NODE=1`），不要求用户装 Node |
| 语音识别 ASR | 本地 Python 服务（`asr/venv` + `asr/models`） | **源码随包、依赖与权重按需安装**：`resources/asr/` 只有约 100 KB，首次点「安装本地离线识别」时由 `prepare.ps1` 建 venv + 装依赖 + 下 small 权重（约 700 MB，落在包内 `resources/asr/`）。没装时控制台正常降级到浏览器引擎，仅离线识别不可用 |

**为什么 `pack.cjs` 必须改名 `electron.exe` → `ORB 控制台.exe`**：
Electron 用"可执行文件是否叫 electron"来判断 `app.isPackaged`。不改名的话
`DATA_ROOT` 不会切到用户目录，桥也不会启动（症状：能起来但显示 hello-world）。

**为什么 electron-builder 要 `asar:false`**：主进程靠 `../bridge.mjs`、
`../.bridge.json`、`../native/dist/` 定位，打 asar 后这些 `..` 会落到
`resources/app.asar`（**只读**），令牌写不进去 → 面板全线 401，桥也起不来。

## 5. 发布到 GitHub 的注意事项

1. **资产文件**：`ORB控制台-1.0.0-便携版.exe`（单文件，**198.5 MB / 208,168,114 B**）。
   GitHub Release 单资产上限 2GB，够用。
   （组成：桩 141,312 B + payload zip 208,026,770 B + trailer 32 B。
     比上一版 165 MB 多出来的 33 MB 就是随包 Python 运行时 103.7 MB 经压缩后的净增。）
2. **SmartScreen 警告**：未签名的 exe 首次运行会弹"Windows 已保护你的电脑"。
   点"更多信息 → 仍要运行"即可。要彻底消除需要代码签名证书（约几百元/年），
   目前没有配，发布时建议在 Release 说明里写一句。
3. **首次运行会解压**：exe 里是 198.5 MB 的 zip，第一次启动会释放到
   `%LOCALAPPDATA%\ORBConsole\_raw\<时间戳>\`，**实测 6.4 秒**（SSD）。
   之后启动就是直接读已解压内容，**1 秒**，不再重复解压。
   同时会解出临时 zip 到 `%TEMP%`，成功即删；失败时**故意保留**并把路径告诉用户，
   让人能手动解开。
4. **ASR 语音：源码随包，权重按需下载**。`resources/asr/` 只有约 100 KB 的源码；
   small 权重（约 483 MB）与依赖（约 200 MB）由用户首次点「安装本地离线识别」时下载，
   **不进发布物**。发布说明里要写清楚这一点（见 §5.5）。
5. **建议同时提供**：
   - `ORB控制台-1.0.0-便携目录.zip`（便携目录版，供想自己看文件的人）
   - `使用说明.md`
   - 本文件 + 4 份 Bug/性能报告（已一并放在 `dist\发布\`）
6. **版本号**：手写在 `orb/desktop/package.json` 的 `version`，
   发版时记得同步改 `orb/pack.cjs` 里的 `VERSION`。
7. **不要提交 `orb/native/dist/` 到仓库**（编译产物）。源码在 `native/src/`，
   别人克隆后跑一次 `native/build.ps1`（三个探针）+ `native/build-sfx.ps1`（自解压桩）
   + `native/build-runtime.ps1`（前台通道 Python 运行时）即可。
   **`pack.cjs` 缺桩时会明确跳过单文件步骤，不会构建失败**；
   但缺 `runtime/python` 或 `asr/` 源码会**直接构建失败**（那是功能缺失，不是可选步骤）。

**关于截图类检查（[5] 的 Screenshot、[8] 的整屏截图、V6）的 ⚠ 环境受限**：
2026-10-15 凌晨实测，开发机 **空闲约 30 秒就进 Modern Standby 并锁会话**
（事件日志 506/566，循环出现），待机/锁屏期间 **BitBlt 对所有进程一起失效**
——自检因此连败，但用全新 python 进程直接 `ImageGrab.grab()` 判别，同样失败，
证明是环境级而非产品故障；数分钟后机器被真实鼠标输入唤醒，同一代码全绿。
注意 **SendInput 合成输入唤不醒 Modern Standby**，所以自检里 orb 工具的鼠标
注入起不到唤醒作用。自检对此的处理：截图项重试 5 次（间隔 3s）后先用
「全新进程直接 grab」判别——环境级记 ⚠（未验证、不计失败），
只有"新进程能截而 MCP 子进程不能"才记 ✗。无人值守跑自检遇到 ⚠ 时，
恢复交互桌面（动一下鼠标）后重跑即可，不要当成产品问题。

## 6. 已知限制

| 限制 | 说明 |
|---|---|
| 只出 Windows x64 | 没配 mac/linux 目标，需要时在配置里加 `mac`/`linux` 段 |
| 没有代码签名 | 见 §5.2 |
| electron-builder 当前不可用 | 代理对 GitHub 502，portable 的 SFX 模块拉不下来；网络恢复后可用 |
| `pack.cjs` 会累积旧构建 | 输出目录带时间戳，每次多占约 510 MB（+ zip/exe），旧的自行清理 |
| 自解压桩依赖系统 `tar.exe` | Windows 10 1803+ 自带；更老的系统自动退 PowerShell `Expand-Archive`。两者都没有才会解压失败 |
| 首次运行需要 ~720MB 可用空间 | 要同时放解出来的目录（490 MB）和临时 zip（199 MB），临时 zip 成功后即删 |
| 桩未做安装/卸载注册 | 它是绿色便携，不做注册表写入；"卸载"就是删掉 `%LOCALAPPDATA%\ORBConsole` |

### 清理旧构建

`orb/清理旧构建.cmd`（内部调 `orb/clean-old-builds.ps1`）：

```bat
orb\清理旧构建.cmd              :: 保留最新 1 份，其余进回收站（删前需输入 YES）
orb\清理旧构建.cmd -DryRun      :: 只列清单不动手
orb\清理旧构建.cmd -Keep 2      :: 保留最新 2 份
```

- 只扫 `dist\` 下的 `ORB控制台-*`，**绝不动 `dist\发布\`**（交付物）
- 走回收站（`Microsoft.VisualBasic.FileIO.FileSystem` 的 `SendToRecycleBin`），
  不是永久删除，误清了能还原
- `pack.cjs` 跑完也会在末尾提示这个脚本
- ⚠️ `.ps1` 必须**带 BOM**：PowerShell 5.1 用 `-File` 执行时按 ANSI(936) 读无 BOM 的
  UTF-8，中文注释和字符串会全乱。`.cmd` 则必须**纯 ASCII**（cmd.exe 按 ANSI 读），
  所以中文全放在 .ps1 里

## 7. 本次构建中修掉的打包缺陷

打包前审计发现现有构建产物缺了 4 项，**会导致发布版功能静默失效**，均已修复：

| 缺陷 | 后果 |
|---|---|
| `native/dist/*.exe` 未打进包 | `orb-input.exe` 缺失 → 键鼠模拟直接报"orb-input 执行失败"；`orb-foreground.exe` 缺失 → 前台追踪退回 PowerShell（白丢性能收益）；`orb-selection.exe` 缺失 → 划词监听退回 `selection-watch.ps1`（白丢性能收益） |
| `mousehook.mjs` 未打进包 | bridge 动态 import 抛错 → 鼠标录制类功能整体失效 |
| `使用说明.md` 只放包根、没放 `resources/extras/` | `ensureBundledExtras` 只认 extras 目录 → 打包态首屏说明永远空手而归 |
| 示例工作流未随包 | 桥读 `DATA_DIR/workflows`，打包态 DATA_DIR 是 APPDATA → 用户一个示例工作流都看不到 |

修复内容：
- `pack.cjs` 新增 `NATIVE_FILES` / `BRIDGE_LOCAL` / `WORKFLOW_SRC`，
  `使用说明.md` 同时复制到包根和 `resources/extras/`，
  校验清单加入 `bridge.mjs` / `mousehook.mjs` / 三个 exe / `extras/使用说明.md`
- `main.js` 的 `ensureBundledExtras()` 扩展为同时种子「使用说明」和「示例工作流」
- electron-builder 的 `extraResources` 同步覆盖这 4 项（`../native/dist` 整目录复制，
  新增的 `orb-selection.exe` 自动包含在内）

> 换句话说：**改这套打包配置之前，先读 §3 的路径契约表**，
> 否则很容易再次漏掉某一项，而且开发态完全测不出来。

### 7.1 2026-10-15 补录：`runtime.mjs` 漏打包（整包起不来）

T02 引入 `orb/runtime.mjs` 后，`bridge.mjs` 顶部多了 `import … from "./runtime.mjs"`，
但 `BRIDGE_LOCAL` 没同步加它。**后果不是某个功能坏，而是整个桥进程
`ERR_MODULE_NOT_FOUND` 起不来**——面板能开，但所有通道全无响应。

为什么前面几轮都没发现：既有的 `must` 校验清单是"**列进去的文件在不在**"，
天生查不出"**该列却没列**"这种错误；而开发态源码就在 `bridge.mjs` 旁边，
`node orb/bridge.mjs` 一切正常。是这次**第一次真跑发布布局**
（`ELECTRON_RUN_AS_NODE=1` 起 `resources/bridge.mjs`）才炸出来的。

修复（两层）：
1. `BRIDGE_LOCAL` 加入 `runtime.mjs`，`must` 清单同步；
2. **新增自动审计**：`pack.cjs` 把拷进包的 `bridge.mjs` 读回来，正则扫出所有
   `from "./X"` / `import("./X")`，逐个断言 X 在 `resources/` 里真实存在，
   缺一个直接构建失败。这是**从消费方反推**，今后新增任何本地依赖都会被强制发现，
   不依赖人记得更新清单。

> 教训沉淀：**"新增一个被 import 的本地模块"必须同时改打包清单，
> 而唯一可靠的验证是"用发布布局真跑一次"**。`selftest.mjs` 与本文 §5.5 的
> 门禁都替代不了这一步——所以 `pack.cjs` 里干脆做了静态审计。

## 8. 为什么弃用 IExpress（完整排查记录）

原本用 Windows 内置的 IExpress 做自解压，**它对本项目的 payload 稳定失败**。
因为失败模式太隐蔽（不是报错，是"卡住"），把排查过程完整记在这里，
免得以后有人又想换回 IExpress 重走一遍。

**现象**：IExpress 返回 1，只留下一个 172,032 字节的残桩和残留的 `~...CAB`。

**逐项排除**：

| 对照实验 | 结果 | 排除掉的假设 |
|---|---|---|
| mini 包（几个小文件） | ✅ 成功 | IExpress 本身可用、SED 写法正确 |
| 旧 zip（164,793,435 B） | ✅ 成功 | 不是环境/权限/长路径问题 |
| 176 MB 单文件随机包 | ✅ 成功 | **不是体积上限** |
| 新包**排除 `orb-selection.exe`** | ✅ 成功 | → 定位到触发文件 |
| 旧包 + 6 字节 dummy（凑到 4374 文件） | ✅ 成功 | **不是文件数** |
| 用同尺寸全零文件替换 | ✅ 成功 | **是文件内容，不是体积** |
| `expand.exe` 展开残留 CAB | ✅ **完全成功**（zip 与 run.cmd 都在） | → **CAB 本身有效，卡在最后的「桩 + CAB」合并步** |

**为什么不手工拼**：试过 `stub + CAB` 直接拼接，无效 —— IExpress 的成品不是简单
拼接（MSCF 头出现在偏移 169,832 处，即桩体内部，成品尾部是零填充），
格式细节无公开文档。本机也没有 7-Zip / WinRAR 可以做参照。

**结论**：失败取决于 payload 的**具体字节**（同尺寸不同内容可稳定复现不同的成败），
且失败点落在无法控制的合并步 —— 这不能作为发布依赖。

**所以自研了 `native/src/orb-sfx.c`**（约 330 行，零依赖，只用 Win32）：
格式完全由我们定义（见 §2），任何一步都能自己复现和调试。
`orb-sfx` 用完整原生的流程替代了 IExpress 的两个不可控环节：

| 环节 | IExpress | 自研桩 |
|---|---|---|
| 压缩 | 内部 MSZIP→CAB（不可选、不可控） | 直接用系统 `tar.exe` 打 zip（与 zip 交付物**同一份字节**） |
| 合并 | 内部私有格式，无文档 | `stub + zip + 32B trailer`，自己的格式 |
| 解压 | IExpress 自己的解压器 | `tar.exe`，退 `Expand-Archive` |
| 可调试性 | 失败时只有残桩 + 残留 CAB | 任何一步都能单独测（`--probe` / `--extract-only` / `test-sfx.cjs`） |
| 产物大小 | 162.8 MB（CAB 压缩） | 165.0 MB（payload 不二次压缩 —— 但 zip 里的 Electron 本来就是 deflate，再压收益边际） |

**顺带修掉的一处语义问题**：IExpress 版 exe 的 payload 是压缩过的 CAB，
所以"已解压过就别再解"这件事只能靠 `run.cmd` 里的 for 循环猜目录名；
自研桩则明确以 `_raw\<子目录>\resources\app\main.js` 是否存在作为判据。真实文件，不是猜。
