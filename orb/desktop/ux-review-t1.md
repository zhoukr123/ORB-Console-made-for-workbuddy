## Q1 对比度独立验算（全部用独立公式重算，与 §4 数值一致 → §4 可信）

| 组合 | 用途 | 我算出 | 门槛 | 判定 |
|---|---|---|---|---|
| `#ffc65c` / `#12162b` | 亮金正文 | **11.47** | 4.5 | ✅ |
| `#f0a92e` / `#12162b` | 主金正文 | **8.87** | 4.5 | ✅ |
| `#f0a92e` / `#171c35` | 主金 on bg-soft | **8.31** | 4.5 | ✅ |
| `#c98a1f` / `#12162b` | 暗金正文 | **6.07** | 4.5 | ✅ |
| `#8a6520` / `#12162b` | 琥珀描边线 | **3.37** | 3.0 | ✅ |
| `#12162b` / `#f0a92e` | 金底深字 | **8.87** | 4.5 | ✅ |
| `#12162b` / `#ffc65c` | 亮金底深字 | **11.47** | 4.5 | ✅ |
| `#ffc65c` / `#3a2c14` | 亮金 on 琥珀底衬 | **8.70** | 4.5 | ✅ |
| `#c98a1f` / `#3a2c14` | 暗金 on 琥珀底衬 | **4.60** | 4.5 | ⚠️ 擦线（余量 0.10） |

**点名要盯的两项：**

- `#c98a1f` / `#3a2c14 = 4.60`：**技术达标，但余量只有 0.10**，落在小字号（11.5px）抗锯齿容差边缘。关键事实：**这个组合在 §3.1 落位表里根本没被实例化** —— `--amber-dim` 只用于 `.more-btn` / `.more-sec` 文字（底是 `--bg`，6.07 ✅）和 `.typing i` 圆点（图形，6.07 ✅）；hover / 选中态虽然底色变 `--amber-soft`，但文字都强制切成 `--amber-bright`（8.70 ✅）。所以真实无风险，但该组合应视为**禁用组合**。
- `#8a6520` / `#3a2c14 = 2.56`：**确实 < 3.0，不达标。** 但该描边只出现在 `.slotnote`（静态说明块，非状态边界），属纯装饰，§4.1 已自我标注。**不得把 `--amber-border` 用于任何「传达状态」的边界。**

**额外发现（顺手算的，供前端备案）：**

- `--amber-soft #3a2c14` 对 `--bg #12162b` 仅 **1.32:1**、对 `--bg-soft #171c35` 仅 **1.24:1** → 琥珀底衬与底色**亮度几乎相同**，全靠色相差（暖棕 vs 冷靛）区分。对红绿色盲用户，这些「填充态」（credit 底、slotnote 底、themecard.on 底、pinned hover 底）**几乎不可辨**。所幸这些态都同时改了边框（`--amber`，8.87 / 6.72 ✅）与文字色，状态不单靠填充，**可接受但需知悉**（建议写进 spec 的「已知局限」，防止后续有人只改填充色不改边框）。
- `.credit` 边框 `--amber-border` on `--bg-soft` = **3.16** ✅（勉强达标，勿再压暗）。

**必须修正项：**

1. **非阻断、但立为守则**：禁止出现 `--amber-dim`(#c98a1f) 文字压在 `--amber-soft`(#3a2c14) 上的组合；若某处确需「次级金字 + 琥珀底」，**改用 `--amber`(6.72) 或 `--amber-bright`(8.70)**。
2. `--amber-border`(#8a6520) 仅限装饰线；如需「可见的状态边界」，替代值为 **`--amber-dim`(#c98a1f)**（vs `--amber-soft` = 4.60 ✅）。

## Q2 `.led.off` 由红改灰是否可辨

**结论：可辨，安全，且比现状更好。**

- 实测 `.led` 尺寸是 **7px**（`panel.html:457`，不是 6px）。
- `.led.off` `--fg-muted #7c85ad` vs 深空底 `#12162b` = **4.95:1** → 远超图形元素 3:1，小圆点清晰可见。
- `.led.on` `--amber #f0a92e` vs 底 = **8.87:1** + 脉冲光环（`ledpulseA` 把外圈从 3px 撑到 6px）→ on 点「看着更大更亮」。
- **决定性证据：这不是纯颜色编码。** 每个灯旁边都有文案 span（`#t-win / #t-orb / #t-dsh`）：**on 显示工具数、off 显示「断开」（`panel.html:1559`）**。所以「这个通道没开」有文字兜底，色弱 / 灰度用户也无障碍。
- off(#7c85ad) vs on(#f0a92e) 直接比 = 1.79:1，但两点不邻接，各自只需对底色达标；且色相差 ~194°+ 脉冲差异 → 一眼可分。

**必须修正项：**

1. **禁用 `--border-strong`(#39406b) 作为 off 色** —— 它 vs 底 = **1.80:1**，约等于隐形（§8 里提过这个候选，直接否掉）。**off 必须保持 `--fg-muted`。**
2. 保留「通道断开」文案作为该状态的 a11y 主证据（**正例：禁止只靠颜色编码**）。

## Q3 「能量三点」与消息区暖晕 → **暖晕：降 α 到 .04**

**三点本身：不构成噪音。** 三角锚点（顶栏标题 / 状态条积分·灯 / 发送键）分处**左上、左中、右下**屏边角，全在正文列之外，不会抢对话焦点。浮层展开、设置面板打开时，金色都收敛在各自区域内（设置面板本就是全幅遮罩，焦点在面板），无叠加问题。

**消息区暖晕：这是全案最大的 a11y 隐患，实测踩线失败。** `.msg .who`（说话人标签，11px，`--fg-muted`）与 `.msg.sys .body`（系统消息，12px，`--fg-muted`）**直接坐在 `.messages` 底色上**（`panel.html:525 / 559 / 1480`）。把 `--amber-wash` 叠到底色后重算：

| 暖晕峰值 α | 混合后底色 | `--fg-muted` 在其上 | 判定 |
|---|---|---|---|
| **.10（= `--amber-wash` 现值，§7 补丁的真实取值）** | #28252b | **4.18** | ❌ 不达标 |
| .08 | #29262b | 4.34 | ❌ |
| .05（§3.3 预算标的） | #20212b | 4.60 | ⚠️ 勉强 |
| **.04** | #1b1c2b | **4.66** | ✅ |

⚠️ **关键矛盾：§7 补丁写的是 `var(--amber-wash)`（= .10），而 §3.3 预算表标的是 0.05。按 §7 原样落地 → 消息区底部说话人标签 / 系统消息会掉到 4.18，违反 WCAG AA。**

**明确结论：降 α 到 .04**（删除也可接受，但**绝不保留 .05~.10**）。理由：.04 把最坏点拉回 4.66（有余量），仍保留一条「贴着底边、呼应 compose 金线」的暖晕；把它当纯氛围，不承担任何正文可读性风险。若坚持口径 B 要 ≥8%，请把差额补到 **header / strip / compose 三处铺层**（这三处铺层背后无正文文字：textarea 是 `--bg` 不透明底、title 是 `--amber-bright` on wash = 9.7 ✅），**不要补在消息阅读面上**。

**语义分工（用户=靛蓝、Orb=琥珀）：成立，误读为「未读 / 警告」的风险为低。** 依据：① Orb 消息自带 who 标签「Orb」+ 独特气泡形状（左对齐、圆角 13/13/13/3），不是孤立色块；② 错误态统一走 `--danger` 红（`.msg.err`），不碰琥珀；③ `--warn` 别名虽 = 琥珀，但实测 t1 下 `--warn` 只被 `.pending`（「排队中 / 执行中」= 进行中）和 `.step-ico.if`（分类图标）使用，**无真正的警告 / 错误占用 `--warn`** → 无冲突。

**必须修正项：**

1. **阻断项**：`.messages` 暖晕从 `var(--amber-wash)`(= rgba(240,169,46,.10)) 改为 **`rgba(240,169,46,.04)`**（建议单独给 token，如 `--amber-wash-faint`）。同时修正 §3.3 预算口径（峰值 .04）。
2. `.msg.orb::before` 提到 opacity .5 后，琥珀条对底 = **3.10:1**（图形达标但接近下限）；`.5` 可接受，若要更「轻」改用 `.4`。不要再往上提。
3. 复核 `--warn` 别名：本轮 OK，但要求前端保证**任何新增的「警告 / 危险」文案不得使用 `--warn`**（危险固定 `--danger`），否则会与「能量琥珀」撞语义。

## Q4 急停从工具区移除后的可发现性 → **移除即可，但必须补 X1+X2**

**现状 6 个入口梳理：**

1. 顶栏 `#stopBtn`（红色圆圈+斜杠图标，title 含热键，`panel.html:1219`）；
2. 工具区 `#toolStop`（`.pinned.danger` **红色 + 文字「急停」**，排在所有工具最前，`2153-2158`）；
3. 热键 `Ctrl+Alt+Backspace`；
4. 命令面板 Ctrl+K（**急停条目排最前**，`3478-3483`）；
5. 设置→关于→快捷键列表（**已列出急停热键**，`1403`）；
6. 设置→安全 pane（现存「危险操作拦截」，**目前无急停说明**）。

**可发现性风险：中。** 移除后，唯一可见的「点得动」的入口是顶栏那枚**纯图标**按钮，且它与录制键**同色（都 = `--danger` #e8736a）、相邻**（CSS 分组就是 [录制 急停]，`1217-1219`）。仅凭颜色无法区分「录制」与「急停」—— 只能靠图标形状（三角 vs 圆圈斜杠）+ hover 动效（录制箭头前冲 / 急停斜杠转 90°）。文字「急停」标签消失后，「这是一键停掉全部自动化」的语义只能从 hover title 获得，学习成本上升。

**误触风险：净下降。** 把「停止一切」这种破坏性动作从**被高频点击的工具行**里拿掉，是安全收益；剩下的风险转移到顶栏 rec/stop 相邻误点，但该风险被图标形状 + hover 动效缓解。整体：**例行误触 ↓，紧急时的「伸手可得」依赖顶栏图标 + 热键**。

**硬约束下的补偿（不改布局 / 尺寸 / DOM，只改措辞与既有属性）：**

- **X1（必做）**：改 `#stopBtn` 的 `title` 与 `aria-label` 措辞，把「停止一切自动化」与「录制」明确切开。建议：
  - 静息 `title`：`急停：立即停止所有自动化（不是停录制）｜热键 Ctrl+Alt+Backspace`
  - `aria-label`：`急停，立即停止所有自动化`
  - 同步 `renderStop()`（`4028-4030`）里 on 态 title 的措辞，保持一致。
- **X2（必做，零 DOM 新增）**：在**既有的** 设置→安全 pane 的 `slotnote`（危险操作拦截说明，`1371-1374`）里**追加一句措辞**（改既有元素文本 = 允许）：
  > `急停入口在顶栏的红色带斜杠图标（或热键 Ctrl+Alt+Backspace）；触发后立即中断所有自动化并卸下触发器，需手动恢复。`

  这样「安全」分区就同时覆盖「危险拦截」与「急停」两个语义。
- **X3（保留，无需改）**：命令面板急停条目已排最前（可发现性兜底）；设置→关于快捷键列表已含急停热键。建议顺带确认命令面板模糊匹配关键字含「停 / 停止 / 急停 / panic」。
- 代码安全：`renderStop()` 对 `#toolStop` 的查询**已有 null 保护**（`4033-4043`），删掉工具键不会报错；`pinnedOrder` 里去掉 `'Panic'` 即可（`2160`）。**这是一个「改一行」的干净移除。**

**必须修正项：**

1. 移除 `#toolStop` **必须同时落地 X1 + X2**；只删不补 → 不可接受（纯图标 + 红红相邻 + 无文字锚点）。
2. `pinnedOrder` 去掉 `'Panic'`，并保留 `renderStop` 的 null 保护（勿顺手删掉那段，留作回滚）。

## 与视觉 / 前端对齐的全局无障碍清单

- **焦点**：`#stopBtn` 移除工具键后仍是可 Tab 元素，`:focus-visible` 走 `.iconbtn` 既有规则（`panel.html:187` 一带）✅；不改 DOM 顺序 → 焦点顺序不变。
- **动效**：新增 `avBreatheA / creditBumpA / ledpulseA` 仅含 transform / box-shadow，且受既有 `html.no-motion`（`:230`）与 `prefers-reduced-motion` 兜底 ✅。请确认新 keyframes 也纳入 `.no-motion` 关闭列表。
- **颜色非唯一编码**：Q2 靠文案「断开」兜底；Q4 靠 title + 命令面板兜底；错误态固定 `--danger`。**建议把「通道断开」文案作为该状态的 a11y 主证据保留。**
- **CSP**：全部改动为 CSS 变量 / 颜色 / 文本，零外链 ✅。
